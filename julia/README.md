# Dorado.jl — Julia port of the particle-routing kernels

A Julia port of dorado's Lagrangian particle-routing core — `make_weight`,
`particle_stepper` and its callees (`random_pick`, `steep_descent`,
`calc_travel_times`, `check_for_boundary`, stranding decisions), the
`run_iteration(target_time=None)` bookkeeping, and `generate_particles` —
from `dorado/lagrangian_walker.py` and the routing parts of
`dorado/particle_track.py`.

Out of scope for this first port: plotting/glue (`routines.py`), the SciPy
analytics (`spatial.py`, `nourishment_*`), `parallel_routing` (superseded by
native Julia threads in a later phase), file I/O beyond the fixture format,
and the `target_time` routing mode.

## Indexing and semantics conventions

- Positions are 0-based `(x, y)` cell indices exactly as in Python
  (`x` = row, `y` = column); grid access is `grid[x + 1, y + 1]`.
- The 9-slot D8 neighborhood keeps the Python slot order
  `[NW, N, NE, W, 0, E, SW, S, SE]`, addressed 0..8 (`A[x, y, k + 1]`).
- All internal arithmetic is Float64 (the Python original promotes float32
  inputs to float64 in weight construction; the port fixes that promotion at
  fixture load).
- Port is bug-for-bug by design: known Python defects (e.g. the exact-seed
  `divmod` behavior on the x axis) are replicated, to be fixed upstream and
  in follow-up ports, not silently here.

## Equivalence doctrine

The Python original routes with NumPy's legacy global MT19937 stream. The
port owns an explicit package-managed RNG (`StableRNGs.LehmerRNG`, seeded
from the fixture manifest) and mirrors the *draw structure* — which draws
exist, from which distributions, in what order — so stochastic results are
distributionally equivalent, not stream-identical. The deterministic
(steepest-descent, diffusion-free) path is held bit-exact against recorded
walks.

The equivalence suite (`test/runtests.jl`) runs against committed goldens
generated by `goldens/generate_goldens.py` from the Python original:

- **init parity** — every constructor-derived field bit-exact
  (`velocity_angle` allows 2 ULP: NumPy/Julia atan2 differ by 1 ULP on some
  cells), plus `make_weight` bit-exact for both bundled workloads.
- **picker parity** — 125 recorded picker cases (random, steep descent,
  seed picker), including NaN-weight and dead-end rows.
- **deterministic walk replay** — a recorded-draw RNG replays the exact
  NumPy draw sequence through the Julia walker and must reproduce the
  recorded walk step-for-step and consume exactly the recorded draws.
- **stochastic distributional parity** — quantiles of final travel times vs
  the mean of five Python seeds (<5% gap), displacement-bin counts, visit
  histograms (L1 band calibrated from golden seed-to-seed noise), and exact
  structural counts.

Run from the repository root:

```bash
julia --project=julia julia/test/runtests.jl
```

## Benchmark

`bench/bench_routing.jl` mirrors `benchmarks/bench_routing.py`: same
workloads (rcm rows 15–16 × cols 137–139, 20 steps; anuga rows 20–29 ×
cols 48–52, 50 steps; counts 500/2500/5000, 3 repeats; `--quick` = anuga,
500 particles, 3 steps, 1 repeat), same timed region (weight construction
and seeding excluded; only `run_iteration` loops are timed), and the same
result JSON schema (schema_version 1). Warmup is one full untimed route —
required for Julia so the timed region excludes first-run compilation.

```bash
julia --project=julia julia/bench/bench_routing.jl --output /tmp/out.json --quick
```

### Baselines (same revision, same machine, 2026-10-30)

Recorded at commit `df863fc` in `bench/results/` (this machine, single
thread; medians, µs per attempted particle-step including frozen particles):

| Workload | Particles | python | numpy (batched) | julia (this port) |
| --- | --- | ---: | ---: | ---: |
| rcm | 500 | 16.79 | 1.88 | 0.72 |
| rcm | 2500 | 16.76 | 1.67 | 1.10 |
| rcm | 5000 | 18.09 | 1.96 | 0.84 |
| anuga | 500 | 16.62 | 1.70 | 0.70 |
| anuga | 2500 | 17.96 | 1.92 | 0.97 |
| anuga | 5000 | 18.81 | 1.97 | 1.41 |

The previously recorded 12–13 µs/step Python figures predate the #5 routing
fixes and are stale; the re-baselined Python backend at `df863fc` is
~16.6–18.8 µs/step, and the batched NumPy stepper (~1.7–2.0) remains the
honest performance reference. The sequential Julia port lands in the same
order as the batched NumPy stepper (see `bench/results/*.json` for the full
records). Threading is deliberately deferred until these baselines justify
the comparison.

## Regenerating goldens

Requires Python with numpy + the pydorado sources (run from the repo root):

```bash
python3 julia/goldens/generate_goldens.py
```

This rewrites `julia/goldens/goldens/`; commit it together with any port
change that intentionally shifts behavior.
